# Ce qui existe aujourd’hui

Les noms des assistants virtuels et ce qu’ils savent faire changent chaque trimestre. Ce module est le seul du programme qui soit daté : il donne une carte des catégories d’applications au 11 novembre 2026, et la façon de vérifier ce qui a changé depuis. Tous les autres modules restent valables quand cette carte change.

Instantané du 11 novembre 2026. Responsable de la mise à jour : la personne qui présente la séance.

## Objectifs

À la fin de ce module, vous serez en mesure :

- de placer les applications auxquelles vous avez accès sur une carte des catégories;
- de dire ce que chaque catégorie peut voir et faire d’elle-même;
- de savoir où vérifier ce qui a changé, au lieu de retenir des versions.

## Une carte en sept catégories

À la réunion de démarrage, Kevin, responsable des technologies de l’information (TI) chez Location Pavois, présente les règles du client sur l’IA. La première : les documents du client ne vont que dans l’assistant approuvé par votre organisation, avec le compte de l’organisation. Pour la respecter, chaque personne de l’équipe doit savoir quelles applications elle a sous la main, à quelle catégorie chacune appartient et laquelle est approuvée pour les documents du client.

Les applications d’aujourd’hui se rangent dans sept catégories :

1. les assistants de clavardage, pour converser, rédiger et analyser;
2. les assistants intégrés à la suite bureautique, dans la messagerie, les documents et les réunions;
3. les assistants de code dans l’éditeur, qui suggèrent du code pendant que vous tapez;
4. les agents de programmation, qui réalisent une tâche de bout en bout dans le terminal, dans l’éditeur ou dans le nuage;
5. les modes de recherche, qui consultent de nombreuses pages Web et citent leurs sources;
6. les assistants de réunion et de transcription;
7. les générateurs d’images, de son et de vidéo.

Les frontières entre ces catégories sont floues. Un même produit en couvre souvent plusieurs : GitHub Copilot suggère du code dans l’éditeur, et son mode agent prépare des demandes de fusion (*pull requests*).

Votre organisation tient la liste des applications approuvées. Pour chacune, elle précise pour quelles données elle est approuvée et avec quel abonnement. Le module sur les données et l’usage responsable revient sur ce point.

## Trois questions pour chaque application

Isabelle, responsable du développement des affaires, joint la demande d’offres de services de Location Pavois dans l’assistant approuvé. À quoi lui sert l’assistant? À repérer les exigences qui demanderont le plus de travail. Que voit-il? Le fichier joint, et rien d’autre. Que fait-il sans lui demander? Il lit le fichier et répond, mais il n’envoie rien à personne. Un assistant de réunion, lui, entend tout ce qui se dit. Selon ses réglages, il peut rejoindre seul les réunions de votre calendrier et envoyer un résumé.

Ces trois questions s’appliquent à chaque catégorie. Les réponses ci-dessous décrivent ce que montraient les pages des fournisseurs le 11 novembre 2026. Elles varient selon le produit, l’abonnement et les réglages : pour une application précise, vérifiez dans sa documentation. Les produits nommés sont des exemples, pas un classement.

#### Assistants de clavardage

Exemples : Claude, Gemini.

Il sert à converser, à rédiger, à résumer ou à analyser un document que vous fournissez. Il voit ce que vous tapez et les fichiers que vous joignez. Avec une extension ou un connecteur (*connector*), il voit aussi les données des autres applications que vous lui ouvrez. En général, il répond sans rien envoyer. Certaines applications exécutent aussi des tâches planifiées : vérifiez ce qui est activé.

#### Assistants de la suite bureautique

Exemples : Microsoft Copilot, dans Microsoft 365; Gemini, dans Google Workspace.

Il sert à rédiger, à résumer et à chercher dans vos courriels, vos documents et vos réunions, sans quitter l’application. Il voit le contenu de l’organisation auquel vous avez accès : courriels, clavardages, documents, réunions, calendrier. Un document partagé trop largement peut donc se retrouver dans une réponse. Il propose une ébauche, que vous relisez avant de l’envoyer. Certains offrent aussi des agents ou des flux de travaux (*workflows*) qui agissent en votre nom : vérifiez lesquels sont activés.

#### Assistants de code dans l’éditeur

Exemple : GitHub Copilot.

Il sert à suggérer du code pendant que vous tapez, et à expliquer du code. Il voit le code du dépôt, sauf les fichiers que les administrateurs ont exclus. Il suggère, et c’est vous qui acceptez ou refusez. Le même produit offre souvent un mode agent, qui relève de la catégorie suivante.

#### Agents de programmation

Exemples : Claude Code, Cursor, le mode agent de GitHub Copilot.

Il sert à réaliser une tâche de programmation de bout en bout, dans le terminal, dans l’éditeur ou dans le nuage. Il voit le dépôt, le terminal et, si vous l’y autorisez, le Web. Il lit le code, modifie des fichiers, lance des commandes et ouvre des demandes de fusion. Ce qu’il fait sans vous demander dépend des autorisations (*permissions*). Par défaut, Claude Code demande avant de modifier un fichier ou de lancer la plupart des commandes; d’autres modes acceptent ces actions d’office. Les agents dans le nuage travaillent sur leur propre ordinateur et vous soumettent le résultat.

#### Modes de recherche avec sources

Exemples : le mode Research de Perplexity, Deep Research de Gemini, la fonction Research de Claude.

Il sert à répondre, sous forme de rapport, à une question qui demande de nombreuses sources. Il voit le Web et, si vous le choisissez, vos courriels, vos fichiers ou vos applications connectées. Sans vous demander, il lance une série de recherches, lit les pages trouvées, puis rédige le rapport. Vérifiez que votre application cite ses sources, puis ouvrez-en quelques-unes. Une citation montre où chercher; elle ne prouve pas que la page dit ce que le rapport lui attribue.

#### Assistants de réunion et de transcription

Exemples : Otter, ZoomMate de Zoom.

Il sert à transcrire une réunion, à la résumer et à en dégager les suivis. Il entend tout ce qui se dit pendant la réunion, et il voit souvent votre calendrier. Selon les réglages, il rejoint seul les réunions de votre calendrier et envoie des résumés ou des suivis. Les règles sur l’enregistrement des réunions viennent de votre organisation.

#### Générateurs d’images, de son et de vidéo

Exemples : Adobe Firefly, ElevenLabs, Veo de Google.

Il sert à produire une image, une voix, une musique ou une vidéo à partir d’une description. Il voit votre description et les fichiers de référence que vous fournissez, comme une image, un extrait vidéo ou un enregistrement de voix. Il produit des propositions, et vous choisissez ce que vous gardez.

## Ce qui change, et où le vérifier

Ce qui était vrai il y a six mois ne l’est peut-être plus. Les noms changent, les fonctions apparaissent ou disparaissent, et les réglages par défaut bougent. Pour savoir ce qu’une application fait aujourd’hui, lisez ses notes de mise à jour (*release notes*) et sa documentation officielle. Votre mémoire, un article ancien ou une publication dans les réseaux sociaux ne suffisent pas.

Cette carte suit la même règle. La personne qui présente la séance la revérifie dans la semaine qui précède chaque prestation, et au moins une fois par trimestre. La liste à revérifier, à la fin de ce module, sert à cette mise à jour.

## Point de contrôle

À main levée : lesquelles de ces catégories utilisez-vous déjà au travail?

En séance, la question se pose pendant que la carte est affichée. Elle donne aussi à la personne qui présente un point de départ sur l’usage du groupe. Si vous lisez seul ou seule, cochez les catégories que vous employez, puis répondez aux trois questions pour l’application que vous utilisez le plus.

## Récapitulatif

Sept catégories couvrent les applications d’aujourd’hui, et votre organisation en approuve certaines, pour certaines données et avec un abonnement précis. Devant chaque application, posez trois questions : à quoi sert-elle, que voit-elle, que fait-elle sans vous demander. Ce que vous savez d’une application se vérifie dans ses notes de mise à jour et sa documentation, pas dans votre mémoire.

## Pour aller plus loin

Ces sujets ne sont pas présentés en séance. Ils servent de référence.

- Certaines capacités ont pris de l’importance : des agents qui travaillent pendant des heures avec peu de supervision, des agents qui utilisent un navigateur ou un ordinateur de bureau, des agents qui travaillent en arrière-plan ou plusieurs à la fois, et des fonctions de mémoire. On parle d’intelligence artificielle agentive (IA agentive, *agentic AI*). Des conventions ouvertes fonctionnent aussi d’un fournisseur à l’autre : `AGENTS.md`, Agent Skills et le Model Context Protocol (MCP).
- Les abonnements gratuits, payants et d’entreprise diffèrent par le traitement des données, les limites et les fonctions. L’abonnement compte autant que le produit.
- Dans un même produit, on choisit souvent le modèle : un modèle plus petit et plus rapide, ou un plus grand et plus capable. Certains produits offrent aussi un réglage de l’effort de réflexion.

Sujets facultatifs :

- les modèles à poids ouverts et les modèles installés localement;
- l’accès par interface de programmation d’application (API) et le coût à l’usage;
- les critères pour comparer des fournisseurs (traitement des données, intégrations, contrôles d’administration, coût), sans classement.

Le sens de chaque terme est dans le [glossaire](../../resources/R-02-glossary.md). Les lectures complémentaires (R-01) donnent les sources, sections « Fondements » et « Rester à jour ».

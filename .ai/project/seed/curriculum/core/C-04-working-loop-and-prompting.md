# C-04 · The working loop and prompting

- **Where it sits:** Common core
- **Who:** Everyone: required
- **Delivery:** Core session, segment 3 (live demonstration)
- **Time:** 10 min

This is the method the whole program rests on. A single prompt rarely produces a finished result. A loop of briefing, inspecting and correcting does, and it is the same loop for an email, a specification and a code change.

## Outcomes

A participant can:

- Run the loop from a rough request to a verified result.
- Write a brief that states goal, context, constraints and what done looks like.
- Give feedback that names the defect instead of asking for "better".

## Topics

### Required

- The loop: **Frame, Give context, Ask, Inspect, Iterate, Verify, Approve, Capture.** One example is carried through the whole session.
- Brief the assistant as you would a capable colleague who is new to the project: the goal and why it matters, the audience, the material, the constraints, what done looks like, the format.
- When the answer has to be grounded, supply the source material instead of asking from memory.
- Iterate with specific feedback: what is wrong, where, and what you want instead.
- Split large tasks into stages. Ask for an outline or a plan before the full output.
- Tell it to ask when information is missing instead of guessing.
- When a conversation goes sideways, start a new one with a better brief. Arguing with a confused conversation rarely works.

### Recommended

- A reusable brief skeleton: goal, context, constraints, output, acceptance criteria, "ask me if anything is unclear".
- Show one or two examples of what good looks like. An example beats a paragraph of adjectives.
- Ask for alternatives, trade-offs, a critique of its own draft, or a list of what it is unsure about.
- What no longer earns its place: magic phrases, role-play incantations, "think step by step", capital letters. Current models respond to clear context and to the effort setting.
- Use the assistant to improve the brief: "what would you need to know to do this well?"
- Keep what works as a reusable template (later, as a skill: [E-03.5](../tracks/engineering/repo-setup/E-03.5-skills.md)).

### Optional

- Few-shot examples, structured output (tables, JSON), plan-then-execute.
- Team prompt libraries and how to keep them maintained.
- Writing prompts for other models and agents.

## Checkpoint

> A weak request on screen. What is missing? Collect three answers before showing the improved brief.

## Practice

The workshop ([S-02](../session/S-02-workshop.md)) is this loop applied to role-specific material.

## Presenter notes

- The live demonstration must include a first draft that is visibly inadequate. If the first result is good, the audience learns that prompting is magic.
- Show that the improvement came from added context, not from clever wording.
- Record the demonstration beforehand and keep the recording ready. Live tools fail in front of an audience.

## Re-verify before each delivery

- The demonstration recording, whenever the tool's interface changes.

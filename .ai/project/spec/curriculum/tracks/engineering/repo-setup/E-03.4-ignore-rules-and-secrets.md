# E-03.4 · Ignore rules and secrets

- **Where it sits:** Engineering track › Repo setup for AI
- **Who:** Required: all engineering roles
- **Delivery:** Engineering track, session 3; also usable self-serve
- **Time:** 15 min

The most common false belief in agent setup is that an ignored file is a hidden file. It is not, and secrets leak through that gap.

## Outcomes

A participant can:

- Explain what an ignore rule does and does not protect.
- Decide what to commit, what to ignore and what to keep away from the agent.
- Set up a check that catches a secret before it is committed.

## Topics

### Required

- `.gitignore` controls what git tracks. It does not control what an agent can read. A secret in an ignored file is still readable.
- Keeping a file from the agent takes a read-deny rule, a sandbox, or both.
- Ignore: secrets and environment files, local agent state and personal settings, caches, build output, large generated artifacts, personal and client data.
- Commit: the shared instruction file, shared settings, project skills, specifications and decisions.
- Secrets never go in prompts, instruction files, examples, memory files, handoffs or commit messages.
- Scan for secrets before commit, and rotate on any exposure.

### Recommended

- A local-only area for private prompts and scratch work, both ignored and read-denied.
- Know which mechanism your tool has: some have their own ignore file, others rely on permission rules.
- Session transcripts live outside the repository in the user's home directory and can contain whatever was pasted. Set their retention.
- Example files with fake values, such as `.env.example`.

### Optional

- Secret managers and short-lived tokens.
- Data-loss-prevention proxies.
- Rewriting history after a leak.

## Checkpoint

> A file is listed in `.gitignore`. Is it safe from the agent? What would make it safe?

## Practice

In a sample repository with a fake secret in an ignored file, ask the agent to summarize the configuration. Then add a read-deny rule and repeat.

## Re-verify before each delivery

- Tool-specific ignore mechanisms and transcript locations.

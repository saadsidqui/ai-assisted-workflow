# X-03 · End-to-end engagement map

- **Where it sits:** Cross-track overlay
- **Who:** Required: all product and experience roles, management, business development · Recommended: all engineering roles · Optional: HR, others
- **Delivery:** Overlay: closing segment of each track session; full version self-serve
- **Time:** 10 min

The program covers AI assistance from the first client meeting to the deliverable. Each track covers its own stage; this map shows how the stages connect, what passes between roles, and where a person signs off.

## Outcomes

A participant can:

- Trace one engagement from opportunity to handover and name the artifact that passes at each step.
- Identify the human gate at each handoff.
- See their own role's input and output in the chain.

## Topics

### Required

- One engagement from start to finish: opportunity, discovery, proposal, kickoff and setup, specification, build, verification, delivery and handover, follow-up. For each stage: where AI assists, what is produced, who approves.
- Artifacts are the interfaces between roles: brief, proposal, specification with acceptance criteria, repository with instructions, reviewed change, tested release, handover document.
- Every handoff names the accountable role and the check performed.
- The same working loop applies at every stage ([C-04](../core/C-04-working-loop-and-prompting.md)), which is what makes the whole reproducible.

### Recommended

- One fictional client used in every track workshop, so each track works on a different stage of the same engagement.
- A template per artifact.
- A light responsibility table.
- Where client policy constrains each stage ([X-01](X-01-working-in-a-client-environment.md)).

### Optional

- Measures per stage.
- Wording for the service catalogue.

## Checkpoint

> Pick the artifact you receive from another role. What would make it twice as useful to you?

## Practice

In mixed groups, annotate the map with one thing each role needs from the role before it.

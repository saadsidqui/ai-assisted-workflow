# C-05 · Context

- **Where it sits:** Common core
- **Who:** Everyone: required
- **Delivery:** Core session, segment 3
- **Time:** 5 min

Generic answers are almost always a context problem. Knowing what the assistant actually has in front of it explains most disappointing results and most surprising ones.

## Outcomes

A participant can:

- Diagnose a poor answer as missing, wrong or excessive context.
- Tell the difference between a fresh conversation and one with project memory.
- State which source wins when sources disagree.

## Topics

### Required

- Output quality follows context quality. The right material beats a clever prompt.
- Relevant, not maximal. Outdated or irrelevant material lowers quality.
- Check what it actually received: did the file upload, was it cut off, can it see the page you mean.
- A new conversation starts blank unless a project or memory feature is on. Know which one you are using.
- Say which source is authoritative, and ask it to flag conflicts instead of blending them.
- Long conversations degrade: early details fade or get summarized. When it drifts, restart with a short summary.

### Recommended

- Durable context versus task context: standing instructions (who we are, conventions, glossary) versus today's request.
- Project features in chat apps (projects, custom instructions, uploaded knowledge, memory): what persists and who else can see it.
- Keep a short project brief and a glossary ready to attach.
- Ask for quotes and sources so a summary can be checked against the original.
- Connected sources (drive, mail, tickets) are powerful and are also a data-exposure decision ([C-07](C-07-data-security-and-responsible-use.md)).

### Optional

- Context budgeting for very large inputs.
- Retrieval and knowledge bases.
- Compaction in long agent sessions ([E-04](../tracks/engineering/E-04-specs-and-context-engineering.md)).

## Checkpoint

> The assistant gave a generic answer. Name two pieces of context that would have changed it.

## Presenter notes

- Demonstrate the same request twice, without and with the source document. The difference does the teaching.

## Re-verify before each delivery

- Names and behaviour of memory and project features.

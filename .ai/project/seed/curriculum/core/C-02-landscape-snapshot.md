# C-02 · Landscape snapshot

- **Where it sits:** Common core
- **Who:** Everyone: required
- **Delivery:** Core session, 3 slides inside segment 2; full version self-serve
- **Time:** 4 min in session, 15 min full

The audience asked for the current state of AI. Names and capabilities change every quarter, so this is the one module that is dated, owned and replaced as a unit. Every other module stays valid when it changes.

## Outcomes

A participant can:

- Place the tools they have access to on a map of categories.
- Say what each category can see and do on its own.
- Know where to check what changed instead of memorizing versions.

## Topics

### Required

- A map of categories with the organization's approved tools placed on it: general-purpose assistants (chat apps), assistants built into the office suite, coding assistants in the IDE, agentic coding tools (terminal, IDE, cloud), research modes that browse and cite, meeting and transcription assistants, image, audio and video generators.
- For each category, three questions: what is it for, what can it see (your files, your screen, your mailbox), what can it do without asking.
- Which tools are approved here, for which data, on which plan (filled in from [X-02](../overlays/X-02-jurisdiction-and-policy-pack.md)).
- The pace: what was true six months ago may not be. Release notes and official documentation are the source, not memory or social media.

### Recommended

- Capability shifts worth knowing this year: agents that work for hours with little supervision, agents that operate a browser or a desktop, background and parallel agents, memory features, and open conventions that work across vendors (`AGENTS.md`, Agent Skills, MCP).
- Free, paid and enterprise plans differ in data handling, limits and features. The plan matters as much as the product.
- Choosing a model inside a product: smaller and faster versus larger and more capable, and the effort setting.

### Optional

- Local and open-weight models.
- API access and usage-based cost.
- Criteria for comparing vendors (data handling, integrations, admin controls, cost), without a ranking.

## Checkpoint

> Show of hands: which of these categories do you already use at work? (This doubles as a baseline for the presenter.)

## Presenter notes

- Put the snapshot date on every slide of this module.
- Rule for the whole program: no model version numbers on any slide outside this module.

## Re-verify before each delivery

- Everything. Re-verify against vendor release notes within a week of each delivery and name an owner for the refresh.
